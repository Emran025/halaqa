# تجربة الجلسة التفاعلية المباشرة

## القرار الملزم

تقدم جلسة القرآن تفاعلاً مباشراً بين **المعلم والطالب فقط**. ويبقى `quran-halaqa` خدمة ويب لحفظ الحالة الرسمية والمصادقة والتفويض وإشارات التفاوض. لا يمر الصوت أو الفيديو أو عرض المصحف اللحظي عبر Laravel أو WebSocket. تنتقل هذه البيانات مباشرة بين الطرفين عبر WebRTC P2P وDataChannel، مع سياسة `host_only` ودون STUN أو TURN أو Relay أو Media Server.

> لا يعني فشل الاتصال المباشر وجود مسار بديل عبر الخادم. تظهر الواجهة حالة `direct_connection_unavailable` بخيار إعادة المحاولة أو إنهاء آمن فقط.

## مسارات البيانات

| البيانات | القناة | هل تُحفظ رسمياً؟ | السلوك في WPF |
|---|---|---:|---|
| طلب/قبول/رفض/إنهاء الجلسة | REST + رسالة حالة WebSocket | نعم | تعكس الشاشة حالة الخادم ولا تستنتجها محلياً. |
| Offer / Answer / Host ICE | WebSocket Laravel الخاص | لا | ترسلها خدمة الإشارة بعد تفويض القناة فقط؛ لا تسجل SDP أو ICE محلياً. |
| الصوت والفيديو | WebRTC P2P | لا | تعرض معاينات محلية وبعيدة وتتحكم بمساراتها محلياً. |
| كتم الصوت وتشغيل/إيقاف الكاميرا | Media Track محلي + DataChannel حالة عرض | لا | تغيّر المسار فوراً وتبلغ الطرف الآخر بمؤشر عرض فقط. |
| صفحة المصحف والآية والمؤشر وطلب الإعادة | WebRTC DataChannel P2P | لا، إلا عند التثبيت | تظهر لحظياً مع وسم أنها مؤقتة؛ يثبت الموضع عبر REST عند اعتماد الحالة. |
| الخطأ والملاحظة والتقييم والتقرير | DataChannel للعرض الفوري ثم REST | نعم | يعرض الحدث فوراً، ثم يحفظه API مع `client_operation_id` أو Outbox SQLite. |
| تسجيل الفيديو | ملف محلي يختاره المستخدم | لا تلقائياً | لا يرسل التسجيل إلى الخادم ولا يرفعه تلقائياً؛ يتطلب إذناً واضحاً ومسار حفظ محلياً. |

## رحلة المستخدم

```text
طلب الجلسة
  -> قبول رسمي
  -> تحميل RealtimeSession من API
  -> تفويض private-live-session.{session_id}
  -> فتح WebSocket للإشارة فقط
  -> تفاوض WebRTC Host-only
  -> اتصال مباشر
  -> محادثة صوت/فيديو + تحكم مصحف/DataChannel
  -> حفظ أحداث المجال الرسمية عبر REST
  -> إنهاء رسمي وتقرير مستقل
```

تتكون شاشة الجلسة من أربع مناطق. الشريط العلوي يعرض اسم الطرف الآخر وحالة الشبكة وحالة الاتصال المباشر والمؤقت. مساحة الوسائط تعرض الفيديو البعيد مع معاينة محلية قابلة للتحريك. المساحة الرئيسة للمصحف تعرض الصفحة، تمييز الكلمة والخطأ، ومؤشر الطرف الآخر. اللوحة الجانبية تعرض المهمة والنطاق والأخطاء والملاحظات وسجل الطلبات السريعة.

| مجموعة التحكم | الإجراءات |
|---|---|
| الوسائط | تشغيل/كتم الميكروفون، تشغيل/إيقاف الكاميرا، اختيار الجهاز، قلب موضع المعاينة، مغادرة الجلسة. |
| المصحف | الصفحة السابقة/التالية، انتقال لآية، متابعة المعلم، إيقاف المتابعة، مؤشر الطرف الآخر، طلب إعادة التلاوة. |
| التقييم | وضع/تعديل/حذف خطأ، ملاحظة، تقييم، تغيير مهمة، حفظ موضع رسمي، إنهاء الجلسة. |
| التسجيل المحلي | بدء/إيقاف تسجيل محلي، عرض مدة التسجيل وحالة المساحة، اختيار مجلد الحفظ، تأكيد صريح قبل البدء. |

## حالة الجلسة

```text
Requested -> Accepted -> Preparing -> Negotiating -> Connected
Connected -> Reconnecting -> Connected
Negotiating/Reconnecting -> DirectConnectionUnavailable
Connected -> Ending -> Ended
```

تدار حالة الجلسة في `LiveSessionStore` ولا تخلط مع حالة المكالمة أو المصحف أو التقرير. تحتفظ `MediaState` بحالة الميكروفون والكاميرا والأجهزة والتسجيل. تحتفظ `MushafPresenceState` بالصفحة والآية والمؤشر المؤقتين. أما `SessionMushafState` الرسمي فيجلب ويحفظ عبر REST فقط.

## التسجيل المحلي والخصوصية

التسجيل **اختياري، محلي، ومرئي للطرف الذي يبدأه**. لا يبدأ التسجيل تلقائياً عند دخول الجلسة، ولا يرسل ملف الوسائط أو مساره أو محتواه عبر WebSocket أو DataChannel أو REST. يجب أن تعرض الواجهة تأكيداً يبين أن التسجيل سيحفظ محلياً، وتوقف التسجيل عند فقدان مصدره أو إغلاق الجلسة، وتحذف أي ملف مؤقت غير مكتمل بعد فشل الكتابة. أي مشاركة مستقبلية للتسجيل تحتاج عقد API وسياسة خصوصية منفصلين، ولا تدخل في هذا الأساس.

## طبقة البيانات في WPF

توجد خدمات واجهية قابلة للاستبدال، ولا تستدعي ViewModels مكتبة وسائط أو WebSocket مباشرة:

```text
Presentation
  -> LiveSessionStore / ViewModel
  -> Use Cases
  -> Domain Ports
  -> Data
      -> RealtimeSessionRemoteDataSource (REST)
      -> LaravelSignalingClient (WebSocket private channel)
      -> IPeerMediaConnection (WebRTC P2P adapter)
      -> IMushafRealtimeChannel (DataChannel adapter)
      -> ILocalVideoRecorder (local file adapter)
```

لا ينفذ هذا الأساس موفر WebRTC خارجي خلسة. أي Adapter فعلي يجب أن يثبت قبل اعتماده أنه يلتزم بـHost ICE فقط، لا يضيف STUN/TURN أو Relay، لا ينقل الوسائط إلى خادم، ولا يغير بروتوكول Laravel الداخلي. يبقى هذا قرار تكامل مستقل بعد اختبار التوافق على Windows.
