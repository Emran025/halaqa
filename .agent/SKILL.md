# Halaqa WPF Client Architecture

## الغرض والنطاق

هذا المستودع هو **WPF Application بلغة C# لسطح Windows** لمنصة Quran Halaqa Live. الخادم الوحيد هو خدمة ويب Laravel في مستودع `samalnashamy780-art/quran-halaqa`، وعقد REST الرسمي هو ملف `quran-halaqa/.agent/openapi.yaml`. لا تُنشأ مسارات أو حقول أو حالات محلية بديلة للعقد. الأدوار الوحيدة هي `teacher` و`student`.

> REST هو مصدر الحقيقة للبيانات الرسمية. الاتصال اللحظي لا ينقل الصوت أو الفيديو عبر الخادم؛ الوسائط والتفاعل الحي P2P مباشر وفق العقد الخلفي.

## ترتيب القراءة قبل التعديل

1. افحص شجرة المشروع الفعلية، ثم اقرأ `.agent/ARCHITECTURE.md` و`.agent/references/canonical-tree.md`.
2. ارجع إلى `.agent/CONTRACT_REFERENCE.md` ثم إلى مسار العملية ومخططها في OpenAPI قبل إنشاء نموذج أو عميل أو حالة واجهة. عند العمل على المصحف أو SQLite أو الخطوط أو معايير الخطأ، اقرأ `.agent/SHAFEEA_REFERENCE_ADOPTION.md` أولاً. وعند لمس الجلسات أو الصوت أو الفيديو أو DataChannel أو التسجيل، اقرأ `.agent/LIVE_SESSION_EXPERIENCE.md` وعقد `REALTIME_CONTRACT.md` أولاً.
3. حدد الدور، الصلاحية، المدخلات، المخرجات، حالة الشبكة، وخطة إعادة المحاولة قبل كتابة الكود.
4. نفّذ التغيير في طبقات الميزة بالترتيب: `Domain` ثم `Data` ثم `Presentation` ثم تسجيل الاعتماديات.
5. اختبر التحويل JSON، حالة الاستخدام، وحالة العرض قبل دمج الميزة.

## القواعد غير القابلة للتفاوض

| الموضوع | القاعدة |
|---|---|
| البنية | لكل ميزة مجلدات مستقلة: `Presentation` و`Domain` و`Data`. لا تعتمد `Domain` على WPF أو HTTP أو JSON أو التخزين. |
| بيانات الشبكة | تستقبل `Data` بيانات الشبكة حصراً عبر مصدر Remote، وتحولها نماذج DTO صريحة من/إلى JSON، ثم تنفذ واجهات Repository الموجودة في `Domain`. |
| الواجهة | Views خالية من منطق الأعمال. تقوم ViewModels باستدعاء Use Cases فقط، ولا تستدعي `HttpClient` أو DTO أو `JsonSerializer` مباشرة. |
| الحالة | حالة الشاشة والتحميل والأخطاء في ViewModel/Store الخاص بالميزة. لا تجعل شاشة أخرى مصدر حالة لشاشة مختلفة. |
| التهيئة | `Config` يجهز HttpClient، المصادقة، التنقل، التخزين الآمن، الإعدادات، وسجلات التطبيق. الميزات تستعمل الواجهات المُسجَّلة فقط. |
| العقد | المفاتيح الجذرية دلالية مثل `user` و`halaqa` و`mistakes`؛ يمنع إدخال غلاف عام باسم `data`. |
| الأخطاء | يترجم عميل HTTP فقط استجابات 401 و403 و404 و409 و422 وفشل الشبكة إلى `Result`/`AppError` قابلة للعرض. لا تخفِ الخطأ باستثناء عام. |
| الخصوصية | لا تخزن محلياً بيانات حساسة للطلاب قبل القبول، ولا تسجل Tokens أو كلمات مرور أو JSON حساس في السجل. |
| التكرار | يولد العميل `client_operation_id` ثابتاً للعملية القابلة لإعادة المحاولة، ويعيد استخدامه عند إعادة المحاولة أو مزامنة الأخطاء. |
| عدم الاتصال | التطبيق متصل افتراضياً. يسمح بالتخزين المحلي الدائم فقط للمصحف، وعناصر/عمليات الأخطاء غير المتزامنة، وجلسة الوصول الآمنة وإعدادات المستخدم الضرورية. |
| المصحف والأخطاء | يقرأ المصحف محلياً من `QuranV3.sqlite` المعبأ مع التطبيق. تخزن عمليات الأخطاء في SQLite Outbox وتزامن عند عودة الشبكة، مع الإبقاء على حالة محلية واضحة: Pending أو Synced أو Conflict أو Failed. |
| اللحظي | يقتصر Laravel وWebSocket على التفويض والإشارة والحالة الرسمية. يمنع إضافة STUN أو TURN أو Relay أو Media Server أو مزود بث خارجي. تمر الصوت والصورة وبيانات المصحف المؤقتة مباشرة P2P، ويفشل الاتصال المباشر بحالة واضحة عند عدم توفره. |

## دورة تنفيذ الميزة

يبدأ العمل بعقد ميزة مختصر يحدد رحلة المستخدم والمسارات ومخططات الطلب/الرد والحالات والصلاحيات. بعد ذلك تُعرّف Entity وValue Objects وRepository Port وUse Cases داخل Domain. ثم تُبنى DTOs وRemote/Local Sources وRepository implementation داخل Data. أخيراً تربط ViewModel/Views والانتقالات داخل Presentation، ثم تسجل مكونات الميزة في `FeatureModule`.

لا تضع endpoint أو مفتاح JSON أو سلسلة مسار داخل ViewModel. لا تمرر DTO إلى واجهة العرض. لا تستخدم ملفات مشتركة لتخزين منطق خاص بميزة واحدة. لا تنشئ Repository بلا سبب؛ وجوده مطلوب هنا لأن مصدر بيانات الميزة Remote وقد يصبح محلياً في المصحف والأخطاء.

## الاستثناءات والاعتماد

ينفذ أي تغير جوهري في Feature منفصل مع اختبارات للمسار الناجح، أخطاء التحقق، عدم الصلاحية، التعارض، انقطاع الشبكة، والتكرار إن كانت العملية قابلة للإعادة. أظهر عند التسليم الملفات المتغيرة، سبب موضعها، ومسار البيانات من View إلى Use Case ثم Repository ثم Remote/Local Source.
